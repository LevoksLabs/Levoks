# Google login and account storage

Set `GOOGLE_ID`, `GOOGLE_SECRET`, `NEXTAUTH_SECRET`, and `NEXTAUTH_URL` in the server environment (locally, the ignored `.env.local`). Restart the server after changing credentials. The Google OAuth client must be a Web application with the exact authorized redirect URI `http://localhost:3000/api/auth/callback/google` for the default local URL. For a deployment, use its HTTPS origin in both `NEXTAUTH_URL` and the Google redirect URI.

Google's stable subject ID identifies each account, independently of display name or email. The browser's projects, embedded assets/source files, checkpoints, groups, stars, trash, conversations, and active-project pointer use that account's storage namespace. Switching accounts hides the old workspace, finishes pending local saves in the original namespace, and reloads to clear editor state. Signing back in restores the account's local projects on that browser. Existing unscoped data stays in the guest workspace because its owner cannot be established; it is never automatically assigned to a Google account.

Cloud projects require `MONGODB_URI` and the existing **Save to account** action. They are stored in the app's database, not Google Drive. Cloud reads and writes use the authenticated session owner; a stale tab cannot save under a different account. Browser-local history and conversations do not sync between devices. Local account separation prevents accidental mixing in the app; browser storage is not a security boundary against someone with access to the browser profile or developer tools.
